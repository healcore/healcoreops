# Как помочь проекту

Спасибо, что хотите помочь! Несколько правил, чтобы всё прошло гладко.

## Сборка

Нужен только Go 1.24+, компилятор C не нужен:

```sh
./build.sh        # Linux/macOS → dist/HealCoreOps-Setup.exe и dist/healcoreops-linux-amd64
build.bat         # Windows
```

Перед отправкой изменений:

```sh
go vet ./... && GOOS=windows go vet ./... && go test ./...
```

## Правила

- Код, специфичный для Windows, — в файлах `*_windows.go`, заглушки — в `*_other.go`.
- Каждая новая строка интерфейса — на двух языках (`internal/web/static/i18n*.js`).
  Строки ядра через `i18n.T("…")` должны иметь перевод в `internal/i18n/en.go` — это проверяет тест.
- Всё, что меняет систему, должно записываться в историю (`Core.Record`) и, если возможно, быть обратимым.
- Ничего не удаляем без подтверждения пользователя; файлы — только в Корзину.
- Твики, которые снижают безопасность или ломают систему (отключение UAC, обновлений, удаление Edge),
  не принимаются.

## Выпуск версии

1. Поднимите номер в `build.sh`, `build.bat`, `internal/core/core.go` (`Version`) и `cmd/setup/main_windows.go` (`appVersion`).
2. Допишите раздел в `CHANGELOG.md`.
3. Прогоните [чек-лист тестирования](docs/TESTING.md) на реальных машинах (разделы 1–2 — обязательно).
4. Создайте тег и отправьте его:

   ```sh
   git tag v1.10.1 && git push origin v1.10.1
   ```

GitHub Actions проверит, что номер версии совпадает с тегом, соберёт установщик и Linux-версию,
подпишет их (если подпись настроена — см. [docs/SIGNING.md](docs/SIGNING.md); в SignPath нужно
одобрить запрос), посчитает SHA-256 и опубликует релиз с этими файлами.
