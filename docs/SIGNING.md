# Подпись кода

Без цифровой подписи Windows показывает при запуске установщика окно SmartScreen
«Windows защитила ваш компьютер», а антивирусы чаще ошибочно срабатывают на утилиты,
которые меняют настройки системы. Подпись это убирает. Сборка в GitHub Actions уже
умеет подписывать релизы двумя способами — нужно только выбрать один и настроить.

| | Вариант А: SignPath Foundation | Вариант Б: свой сертификат |
|---|---|---|
| Цена | бесплатно для открытых проектов | от ~$200/год (OV) или ~$300+/год (EV) |
| Издатель в окне Windows | **SignPath Foundation** | ваше имя или организация |
| Ключ | хранится у SignPath (HSM), вы его не видите | у вас, в секретах GitHub (OV) или на токене (EV) |
| Одобрение каждого релиза | вручную в SignPath | не нужно |

Сборка подписывает в два шага: сначала саму программу `HealCoreOps.exe`, затем
пересобирает установщик с подписанной программой внутри и подписывает его.
Подпись выполняется только для тегов `v*` (релизов) и только когда она настроена —
без настроек сборка работает как раньше и выпускает неподписанные файлы.

## Вариант А — SignPath Foundation (бесплатно)

### 1. Проверьте условия

Главное из [условий SignPath Foundation](https://signpath.org/terms):

- лицензия OSI для всего кода, без коммерческой двойной лицензии — у HealCoreOps MIT ✓;
- подписываются только собственные сборки из этого репозитория, собранные в CI ✓;
- проект уже выпущен (есть релизы) и активно поддерживается;
- на главной странице и странице загрузки — раздел «Code signing policy»
  (готов: [CODE_SIGNING_POLICY.md](CODE_SIGNING_POLICY.md), ссылка есть в README) ✓;
- двухфакторная аутентификация на GitHub и в SignPath у всех участников;
- программа не меняет систему без предупреждения и умеет удаляться ✓ (все изменения —
  с предупреждением и откатом, есть деинсталлятор);
- нельзя: вредоносные и потенциально нежелательные программы, а также «инструменты,
  обходящие механизмы защиты».

> ⚠️ **Обратите внимание.** Твик «Отключить Microsoft Defender» формально может
> попасть под «обход механизмов защиты». В HealCoreOps он закрыт предупреждениями,
> требует прав администратора и откатывается, но решать будет модерация SignPath.
> Если заявку отклонят из-за него — твик можно убрать из сборки. Администраторы уже
> сейчас могут запретить его политикой `DisableDefenderTweak` = 1.

### 2. Подайте заявку

1. Откройте [signpath.org](https://signpath.org/) → **Apply** и заполните форму:
   репозиторий `github.com/healcore/healcoreops`, лицензия MIT, сайт — страница
   релизов на GitHub.
2. Дождитесь одобрения (обычно от нескольких дней до пары недель). Вам создадут
   организацию в SignPath.

### 3. Настройте проект в SignPath

1. **Trusted Build Systems** → добавьте предопределённую систему **GitHub.com** и
   привяжите её к проекту.
2. **Projects** → проект со slug `healcoreops`.
3. **Artifact configurations** → создайте две конфигурации:
   - slug `app` — содержимое из [`.signpath/artifact-configurations/app.xml`](../.signpath/artifact-configurations/app.xml);
   - slug `installer` — из [`.signpath/artifact-configurations/installer.xml`](../.signpath/artifact-configurations/installer.xml).
4. **Signing policies** → политика `release-signing` с сертификатом SignPath Foundation
   и ручным одобрением (Approvers — вы).
5. **Users** → создайте пользователя для CI (CI user) с правом Submitter в этой
   политике и получите его **API token**.

### 4. Настройте репозиторий GitHub

**Settings → Secrets and variables → Actions:**

| Тип | Имя | Значение |
|---|---|---|
| Secret | `SIGNPATH_API_TOKEN` | API-токен CI-пользователя |
| Variable | `SIGNPATH_ORGANIZATION_ID` | ID организации (Settings в SignPath) |
| Variable | `SIGNPATH_PROJECT_SLUG` | `healcoreops` (можно не задавать — это значение по умолчанию) |
| Variable | `SIGNPATH_POLICY_SLUG` | `release-signing` (тоже по умолчанию) |

### 5. Выпустите подписанный релиз

```bash
git tag v1.10.0 && git push origin v1.10.0
```

Сборка дойдёт до шага **Sign app (SignPath)** и будет ждать (до часа). В SignPath
появится запрос на подпись — одобрите его. Затем то же для установщика. После этого
релиз на GitHub получит подписанные файлы.

## Вариант Б — свой сертификат (.pfx)

Подходит для OV-сертификата, выданного в виде файла `.pfx`. (EV-сертификаты с 2023 года
выдаются только на аппаратных токенах или в облачных HSM — их так подключить нельзя,
нужен подписывающий сервис провайдера.)

1. Закодируйте сертификат в base64:
   - Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard`
   - Linux/macOS: `base64 -w0 cert.pfx`
2. **Settings → Secrets and variables → Actions → Secrets:**
   - `WINDOWS_CERT_PFX` — строка base64;
   - `WINDOWS_CERT_PASSWORD` — пароль от `.pfx`.
3. Выпустите релиз тегом `v*`. Сборка подпишет файлы утилитой `osslsigncode` с меткой
   времени DigiCert и проверит подпись.

Если настроены оба варианта, используется SignPath.

## Проверка подписи

В Windows: правый щелчок по `HealCoreOps-Setup.exe` → **Свойства** → вкладка
**Цифровые подписи**. Или в PowerShell:

```powershell
Get-AuthenticodeSignature .\HealCoreOps-Setup.exe | Format-List Status, SignerCertificate
```

Подпись не даёт мгновенной «репутации» в SmartScreen: OV-сертификат (в том числе
SignPath Foundation) набирает её по мере скачиваний, поэтому первые недели
предупреждение ещё может появляться, но реже и с указанием издателя.
